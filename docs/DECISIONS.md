# Decisions log

Judgement calls made while building, per `CLAUDE.md`. Format: date · decision · why.

| Date | Decision | Why |
|---|---|---|
| 2026-11-21 | **One client shell for `/s/*`** (`app/s/[[...path]]`), with views switched by `history.pushState` instead of App Router navigation. | App Router fetches RSC payloads from the server on navigation, which fails offline. Once the shell is cached, profile, serve and pending views work with no network. A cold deep link opened offline falls back to the cached `/s` shell. |
| 2026-11-21 | **`lead_pin_hash` column added to `stations`** (not in DataModel). The lead PIN gives `station_lead` at join, and approves food-duplicate overrides via `request_lead_override` → one-shot `lead_overrides` row. | DataModel needed a way to make someone a Station Lead and to validate overrides. The confidential `role_pin` stays separate so medical/counselling access is still deliberate. |
| 2026-11-21 | **Offline food override** is accepted as `override_by = "offline:<lead name> via <volunteer>"` and raises a `leads` flag for review. | Bcrypt PIN hashes must never be sent to devices (6-digit PINs are brute-forceable), so a lead PIN can't be checked offline. The duplicate guard protects fairness, not data, so allowing the override with a visible flag is an acceptable trade. |
| 2026-11-21 | **`station_secrets` table** (service-role only, AES-256-GCM with a key derived from `JOIN_TOKEN_SECRET`) stores a recoverable copy of PINs. | Posters must print the PIN, but `stations` only holds bcrypt hashes. Training PINs are stored as `training:<pin>` and only decrypt for `is_training` editions. |
| 2026-11-21 | **Join links** use random tokens whose SHA-256 is stored in `station_join_tokens`, not HMAC-signed JWTs. | Revocable, no shared secret in Postgres, and verification lives entirely in `join_station_token`. |
| 2026-11-21 | `edition_id` **denormalised onto `visit_needs` and `flags`**. | Supabase Realtime `postgres_changes` can only filter on a column of the changed table (`edition_id=eq.<id>`). |
| 2026-11-21 | **Need states:** `referred` means "pending because another station referred them". Pending lists show `pending` + `referred`. A referral never downgrades `pending`; it does reopen a `served` need. | Keeps the PRD's Pending / Served / Declined / Referred chips without a separate queue table. |
| 2026-11-21 | **RLS for idempotent upserts:** registration sessions may read visit-less beneficiaries of their org; sessions may read flags they created. (migration `…006`) | `INSERT … ON CONFLICT DO NOTHING` applies SELECT policies to the proposed row. Without this, offline registrations could never sync. Covered by `tests/03_upsert_sync.sql`. |
| 2026-11-21 | **Card conflict on sync** (two offline devices used the same card): the visit is re-sent without a card code and a `card_conflict` flag goes to leads. | No lost registrations. The coordinator sees it in the data-quality alerts and hands out a new card. |
| 2026-11-21 | **Offline snapshot holds `phone_last4`, not full phone numbers.** | Data minimisation on lost devices. Full phones are only on devices that registered that person, and in the admin console. |
| 2026-11-21 | **Stock may go negative** when offline devices overdraw. | Recording what was really given matters more than blocking. The dashboard shows negative stock in red. |
| 2026-11-21 | **Confidential views by station sessions are not audited per read; admin reads (break-glass) are.** | Station staff read their own notes constantly, so one audit row per glance would swamp the log. Break-glass and `get_confidential` by admins are always logged. |
| 2026-11-21 | **Exports never include confidential payloads**, even for super admins. Phone numbers appear only for people with follow-up consent. | NDPA minimisation. Break-glass, per person and time-boxed, covers the rare legitimate need. |
| 2026-11-21 | **Fuse search runs on the main thread**, not in a Web Worker. | For ≤ 5,000 people, index build and search measure well under the 50 ms budget. A worker would add complexity and bundle weight. Revisit if editions grow. |
| 2026-11-21 | **supabase-js is lazily imported in the volunteer app.** | With secondary views also lazy-loaded, `/s` initial JS is 189.5 KB gzip (budget 200 KB). The shell renders from IndexedDB first. |
| 2026-11-21 | **Dashboard KPIs are computed on demand** by `dashboard_stats` (5 s polling plus realtime nudges), not a materialised view. | Well under 100 ms on 5k people / 30k services. Simpler, and always matches ground truth. |
| 2026-11-21 | **Report route is `/api/reports/summary`** (no `.pdf` suffix); exports accept `?format=xlsx|csv`. | Next.js route segments with dots complicate dynamic params. The content type and filename are still PDF/XLSX. |
| 2026-11-21 | **i18n:** UI strings are English and inline in components for v1. | The PRD lists English for v1. Extracting to `src/lib/i18n/en.json` is a mechanical follow-up before adding Pidgin/Hausa. |
| 2026-11-21 | **Open PRD questions (date, turnout, devices, checkout station, SMS)** were answered with defaults: draft edition "Gratitude Outreach 2026" on 12 Dec 2026, checkout station kind is supported but not created by default, no SMS. | None block the build. Confirm with the outreach team. |
| 2026-11-21 | **Primary buttons and the scan button use `leaf-600` (#136F0E) instead of `leaf` (#188B12).** | White on `leaf` measures 4.42:1, just under WCAG AA 4.5:1 (axe flagged it). DesignSystem already recommends `leaf-600` for buttons, and it reads better in sunlight. `leaf` stays for accents, bars and borders. |
| 2026-11-21 | **PIN lockout: 5 failures per phone, 30 per IP** (5-minute window), not 5 per IP. | Phones at the venue share one public IP. 5 per IP would let a few honest typos lock out every volunteer. 30 still makes brute force useless against 1,000,000 PINs. |
| 2026-11-21 | **Each phone pulls a delta every 30 s** with the heartbeat, in addition to Realtime. | The load test showed Supabase Realtime dropping fan-out under bursts. The delta guarantees every phone catches up, for one small request per phone every 30 s. |
| 2026-11-21 | **After a session ends, the local database is locked for that page** (`SessionEndedError`) before it is deleted. | The revoke test showed an in-flight sync could re-create data on a wiped phone. Locking makes the purge final. |
| 2026-11-21 | **Text sizes are `rem`, not `px`.** | Type then scales with the phone's font-size setting (NFR: works with large system fonts). |
| 2026-11-21 | **Error monitoring is a scrubbed beacon to `/api/client-errors` (server logs), not Sentry.** | No extra vendor holding data during an NDPA-sensitive event. Sentry can be wired into one function later. |
